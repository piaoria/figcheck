# 요소 선택·시각 비교 — 0.2.3

사용자가 Figma 노드와 DOM을 각각 고르는 도구입니다. 요소 선택 버튼 → 페이지에서 클릭하거나 Elements의 `$0`를 사용합니다. 자동 매칭이나 전체 페이지 분석을 하지 않습니다. 결과에는 차이 개수, supported 속성만의 일치율, 나란히 놓인 디자인/웹 값, 색 견본과 크기 막대가 표시됩니다. 양쪽 모두 supported가 아니면 확인 불가 목록으로 이동하고 점수에서 제외합니다.

## 단축키와 수명

Ctrl+Shift+X는 Chrome의 확장 command로 등록됩니다. DevTools가 열린 탭의 페이지에서 작동하며 다른 DevTools 탭이 보여도 선택 모드를 시작합니다. 선택 결과를 보려면 FigCheck 탭을 엽니다. DevTools가 닫혀 있으면 F12 배지와 안내가 표시됩니다. 이 키는 OS 전역 단축키가 아니며 Chrome/OS/다른 확장과 충돌할 수 있습니다. 사용자가 `chrome://extensions/shortcuts`에서 확인·변경할 수 있습니다. DevTools의 FigCheck 화면에 포커스가 있어도 같은 키가 지원됩니다.

선택 모드의 소유자는 지속되는 DevTools 페이지 하나입니다. 버튼으로 시작한 선택은 FigCheck 패널을 벗어나면 취소됩니다. command로 시작한 선택은 다른 DevTools 탭에서도 유지됩니다. Esc·재실행·페이지 이동·브라우저 탭 숨김은 정리합니다. Elements의 새 선택은 전용 선택 참조를 해제합니다. DevTools 종료 후 1.5초 lease와 250ms 검사에 의해 보통 1.75초 이내 overlay·리스너·참조가 제거됩니다. 브라우저가 타이머를 늦추면 실제 정리도 늦을 수 있습니다.

작업 순번으로 이전 start/stop/pulse 응답을 무시하고, 페이지 안에서도 오래된 작업이 새 상태를 덮지 않도록 합니다. 오래된 command와 다른 탭 command는 무시합니다. 임의 시간 지연으로 새 실행을 맞추지 않습니다. 키의 중복 전달만 짧게 제거합니다.

## 대상과 제한

최상위 문서의 HTML 하나를 선택합니다. iframe 내부·SVG·open Shadow DOM 내부는 이유와 함께 선택 불가입니다. closed Shadow DOM은 내부를 관측할 수 없어 host 요소까지만 평가됩니다. 페이지 이벤트를 capture 단계에서 차단하여 버튼/링크의 원래 클릭을 막지만, 먼저 등록된 페이지 capture 핸들러까지 되돌릴 수는 없습니다. 브라우저 내부 페이지 등 inspectedWindow 접근이 제한되는 대상에서는 오류를 표시합니다.

Chrome의 공식 panels.show는 Chrome 140부터 제공되지만, 현재 Chromium은 userAction이 지정된 일부 DevTools 콜백에서만 show 요청을 보냅니다. runtime 메시지/extension command에서는 자동 탭 활성화를 수행하지 않으므로 선택 컨트롤러와 패널 표시를 분리했습니다. 권한 확장이나 private API 우회는 사용하지 않습니다. [공식 panels API](https://developer.chrome.com/docs/extensions/reference/api/devtools/panels), [공식 commands API](https://developer.chrome.com/docs/extensions/reference/api/commands), [Chromium ExtensionAPI 구현](https://github.com/ChromeDevTools/devtools-frontend/blob/main/front_end/models/extensions/ExtensionAPI.ts)을 참고하세요.

격리 Chrome에서 실제 worker → DevTools → 페이지 선택 → FigCheck 결과 전달 및 패널 포커스의 실제 키 입력을 검증했습니다. OS 키 → Chrome commands 발생 자체는 사용 가능한 자동화 도구에서 확인하지 못했습니다. 이는 등록/라우팅/선택 동작 검증과 구분합니다.
