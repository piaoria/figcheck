# 0.3.22 — Alt 거리 측정 재진입

수정 전 0.3.21에서 브라우저 입력(Playwright keyboard, DOM `isTrusted=true`)으로 포인터 고정/이동, 반복 Alt, 스크롤 후 재진입은 통과했습니다. 물리적 Windows 키나 브라우저 메뉴 활성화를 같은 조건으로 재현한 것은 아닙니다.

반면 Alt keydown이 문서 포커스 복원보다 먼저 도착한 상태를 합성 이벤트로 재현하면 실패했습니다. `pinPaint()`가 `document.hasFocus() === false`에서 표시 정리와 함께 `altHeld`도 false로 만들었고, 포커스 회복 처리도 없어 다음 측정 의도가 사라졌습니다. 사용자 환경의 단일 원인이라고 단정할 수는 없지만 코드의 재현 가능한 결함입니다.

표시/B 정리와 키 상태 초기화를 분리했습니다. 일시적인 포커스 미복원에서는 새 Alt 입력 의도를 보존하고 focus 이벤트에서 보존된 좌표로 최신 hit-test를 수행합니다. Alt 해제와 실제 blur에서는 B/거리만 정리하며 A와 좌표는 유지합니다. blur 뒤에는 새 Alt 입력으로 회복합니다.

측정에 실제 사용된 단독 Alt 제스처의 keyup에 한해서 기본 메뉴 동작을 취소합니다. 다른 키가 섞인 Alt 단축키, Ctrl/Shift/AltGraph, 입력 필드 및 측정에 사용되지 않은 Alt는 취소하지 않습니다. 휠은 계속 네이티브 동작입니다. Windows 메뉴 포커스 전환 가능성을 줄이는 제한된 처리이며, 물리적 OS 메뉴 이벤트를 확인했다는 의미는 아닙니다.

`artifacts/picker-depth-results.json`의 `altReentry`에는 브라우저 입력 이벤트 추적을, `altProtection`에는 합성 이벤트 취소 여부를 별도로 기록합니다. 비교/탐색/자동 갱신과 오버레이 스타일은 유지합니다. README 최종 정리·커밋·푸시·외부 업로드는 보류합니다.
