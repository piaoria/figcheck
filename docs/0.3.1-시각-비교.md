# FigCheck 0.3.1 시각 비교

단일 Figma 노드와 사용자가 선택한 웹 DOM을 비교합니다. DevTools 결과에서 **구조 / 색상 / 폰트 정보**를 펼치세요. 넓은 패널에서는 Figma가 좌측, 웹이 우측이며 480px 이하에서는 위아래로 표시합니다. 기본은 접힌 상태입니다. Figma 플러그인은 해당 카테고리 안에서 선택한 노드의 정보만 보여줍니다.

구조 항목을 누르면 비교 표의 해당 행으로 이동합니다. 확인 불가·미지원·사용자 제외 항목은 자세한 이유로 이동합니다. Enter/Space로 펼치거나 항목을 선택하고 Tab으로 이동할 수 있습니다. 이전의 비교 항목 설정, JSON 가져오기, 요소 선택, 접기, 테마와 도움말을 그대로 사용합니다.

## 구조 읽기

width/height는 양쪽에 같은 배율을 적용합니다. SVG의 크기 맞춤은 비교 쌍 전체의 최대 크기로 계산하므로 각 도형을 독립적으로 확대하여 차이를 감추지 않습니다. 숫자는 원본 px 값입니다. +138px 차이는 유지하며 작은 부동소수점 border 오차는 기존 비교 엔진의 판정을 따릅니다.

padding 4방향과 border 4방향의 값은 별도 표시합니다. padding 표시는 방향 기호이며 실제 내부 공간의 비례 표현이 아닙니다. border 선 두께도 가독성을 위한 기호입니다. 각 모서리 radius는 같은 배율의 근사 곡선이며 실제 UI 재현이 아닙니다. 인접 radius 합이 크기를 넘거나 필요한 값이 없으면 모양은 N/A로 표시하고, 원본 숫자를 임의 축소하거나 clamp하지 않습니다. 비대칭 값은 네 방향·네 모서리별로 유지합니다.

margin은 수집하지 않으므로 생략합니다. row gap과 column gap은 별도 숫자로 표시하며 padding과 합치지 않습니다. transform 등의 사유로 크기가 비교 불가하면 도형도 N/A입니다. 실제 0은 0으로 표시하고 unknown을 0으로 바꾸지 않습니다.

Figma의 width/height는 로컬 레이아웃 크기입니다. JSON schema 1.0에는 strokesIncludedInLayout 정보가 없으므로 Figma content 크기를 추정하지 않습니다. Figma 도형은 수집한 레이아웃 경계이며 CSS border-box라고 단정하지 않습니다. 웹 content는 알려진 border-box 크기·padding·border 값과 box-sizing, overflow, scrollbar-gutter 조건이 충족될 때만 계산합니다. 스크롤바 가능성, 미지원 값, 음수 결과는 이유가 있는 N/A입니다.

## 색상 읽기

배경·텍스트·border 각 방향의 색을 같은 체크무늬 배경에 표시합니다. 원본 RGBA의 알파를 유지하며 alpha 0도 유효한 투명색입니다. HEX/RGB/HSL 설정은 색상 표기만 바꾸고 JSON, 비교값, 일치율은 바꾸지 않습니다. gradient, P3 또는 복합·알 수 없는 값은 임의의 단색으로 그리지 않습니다.

이 미리보기는 **paint 자체의 alpha**입니다. 노드 opacity, 조상 opacity, 배경 합성이나 화면의 최종 픽셀색을 재현하지 않습니다. opacity 비교는 기존 별도 속성으로 남습니다.

## 폰트 정보 읽기

fontFamily, fontSize, fontWeight, lineHeight, letterSpacing을 나란히 표시합니다. 불일치 강조는 기존 비교 엔진의 결과만 따릅니다. 요청한 폰트명은 실제로 렌더된 글꼴·fallback을 증명하지 않습니다. 샘플 텍스트를 해당 글꼴로 렌더하거나 폰트를 다운로드하지 않습니다. 모든 라벨은 앱의 기존 UI 글꼴을 사용합니다.

## 점수와 범위

기존 스키마와 비교 엔진은 유지합니다. 추가 도식은 점수 분모를 늘리지 않으며, 설정에서 제외한 항목도 N/A로 표시합니다. 일치율은 양쪽 supported이며 포함된 속성만 계산합니다. CSS 원인 후보·cascade 추적 한계는 기존과 동일합니다. 자동 매칭, 전체 페이지 분석, AI, Tailwind 수정 제안, 새 권한과 외부 전송은 추가하지 않았습니다.

## 설치와 검증

Chrome 확장은 기존 확장 항목에서 새 dist 폴더를 가리키고 새로고침한 뒤 DevTools를 다시 열어 사용하세요. Figma는 개발 플러그인을 닫고 새 manifest/code/ui 빌드를 다시 로드하세요. 사용자 프로필에 자동 설치하거나 전역 브라우저 설정을 바꾸지 않았습니다. 자세한 절차는 [설치·사용](설치-사용.md), 검증 범위는 [검증](검증.md)을 확인하세요.

실제 격리 Chrome DevTools와 실제 빌드 UI를 검증합니다. Figma는 Plugin API mock 호스트에서 시험하며 실제 Figma 호스트 시험과 구분합니다. 물리 OS 단축키와 실제 Figma 설치는 사용자 환경에서 확인해야 합니다.

공식 근거: [Figma strokesIncludedInLayout](https://developers.figma.com/docs/plugins/api/properties/nodes-strokesincludedinlayout/), [CSS scrollbar-gutter](https://www.w3.org/TR/css-overflow-3/#scrollbar-gutter-property), [CSSOM resolved values](https://www.w3.org/TR/cssom-1/#resolved-values).


## 0.3.1 영역 구분과 상태 표시

테두리(border) 영역 안에 내부 여백(padding) 영역을 중첩합니다. 모서리(round)는 별도의 외부 여백 층이 아니라 네 모서리의 속성으로 배치합니다. 방향별 값 옆에는 표에서 사용하던 같은 SVG 아이콘을 사용합니다. 도식 내부의 가운데 크기 경계만 양쪽에 같은 배율을 적용합니다. 중첩 영역의 폭·높이·두께는 분류를 위한 기호이며 실제 레이아웃 비례가 아닙니다.

상단·하단·좌측·우측·내부·외부 용어를 표, 도식, 도움말, tooltip과 접근성 이름에 통일했습니다. 기본 Figma 목록은 추출한 값만 보여주므로 상태 열과 반복적인 추출 성공 요약을 제거했습니다. 자세히 보기의 미지원·미확인 상태와 이유는 유지합니다. DevTools의 가져오기·선택 성공 배지도 반복하지 않으며 일치·차이 판정과 일치율은 유지합니다. 초기 대기, 추출 중, 복사 결과, 오류와 복구 안내는 계속 표시합니다.

기존 JSON·비교 수치·점수·색상·폰트 메타데이터·설정·요소 선택 흐름은 같습니다. 사용 중인 개발 플러그인과 확장을 다시 로드해 새 빌드를 사용하세요.
