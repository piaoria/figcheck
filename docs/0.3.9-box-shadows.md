# 0.3.9 · 박스 그림자 규격 비교

이 문서는 0.3.9 이력입니다. 현재 지원 조건과 표시는 [0.3.10 수정](0.3.10-shadow-visibility.md)을 참고하세요.

일반 박스의 Drop shadow / Inner shadow와 DOM `box-shadow`만 비교합니다. 그림자 수치의 일치는 실제 픽셀·합성·시각적 완전 일치를 뜻하지 않습니다. 기존 DOM 깊이 탐색은 유지합니다.

## 근거와 보수적 대응

확인일: 2026-10-06.

- [Figma Effect API](https://developers.figma.com/docs/plugins/api/Effect/)에서 shadow의 offset, radius, spread, color/alpha, visible, blendMode, showShadowBehindNode를 확인했습니다. spread가 생략되면 0, showShadowBehindNode가 생략되면 false입니다. 새 effect 종류도 있으므로 미지의 visible effect를 '없음'으로 취급하지 않습니다.
- [CSS shadow blur 규격](https://www.w3.org/TR/css-backgrounds-3/#shadow-blur)은 CSS blur와 Gaussian 표준편차의 관계를 설명하지만 Figma raw radius와의 동일성을 보장하지 않습니다. layer/background blur에 쓰이는 변환을 shadow에 적용하지 않습니다.
- [Figma getCSSAsync](https://developers.figma.com/docs/plugins/api/node-properties/#getcssasync)는 Inspect 패널 CSS를 반환합니다. 따라서 그 `box-shadow`의 blur를 비교 기준으로 사용하고 raw effect.radius는 별도로 보존합니다. API가 실패·지연되거나 변수를 포함해 정규화할 수 없으면 미수집/미지원으로 남깁니다. raw radius와 CSS blur의 무조건적인 1:1 또는 2:1 변환은 없습니다.

CSS와 raw effect의 외부/내부, X/Y, spread, RGBA 근거가 유일하게 대응될 때 원본 effect index를 연결합니다. raw와 CSS 색 직렬화 사이의 rounding은 최대 1 sRGB 채널 및 .005 alpha 범위에서 대응 식별에만 허용합니다. 실제 비교 허용오차는 기존 설정의 px/channel/alpha 및 float epsilon을 사용합니다. 중복된 식별 후보가 있으면 blur를 이용해 관계를 추측하지 않습니다.

## 지원 범위

- RECTANGLE, 또는 visible solid fill과 clipsContent가 있는 FRAME/COMPONENT/INSTANCE의 박스.
- NORMAL blend 외부/내부 그림자. 여러 겹과 숨겨진 effect의 원본 index를 보존합니다.
- 그룹·텍스트·벡터, cornerSmoothing, 자기/조상 transform, 비표준 blend, 조상 effect 합성, visible blur/noise/texture/glass/새 effect, showShadowBehindNode=true는 제외합니다.
- 웹은 단일 HTML border-box이며 filter/backdrop-filter, text-shadow, 비표준 blend 및 기존 geometry 제외 사유가 있으면 그림자 비교를 제외합니다. `filter: drop-shadow`를 box-shadow로 취급하지 않습니다.
- 스택 일부가 대응 불가이면 해당 스택 전체를 제외합니다. 나머지 레이어만 비교해 완전한 스택처럼 보이지 않게 하기 위한 제한입니다. 원본 근거는 추가 정보에 남습니다.

## 구조와 비교

교환 문서 `schemaVersion: 1.0`에 선택적 `node.shadows` 확장을 추가했습니다. `shadows.version: 1`은 별도로 검증하며 `schemas/figcheck-shadows-1.schema.json`에 독립 규격을 둡니다. 기존 JSON을 새 버전에서 읽을 수 있으며, 필드 부재는 '그림자 미수집'입니다. `status:supported,layers:[]`는 수집된 '없음'입니다. 예전 앱은 확장 필드를 인식하지 못할 수 있으므로 새 JSON은 0.3.9에서 사용합니다.

CSS의 함수 괄호 깊이를 인식해 최상위 쉼표만 분리합니다. rgba/HSL 내부 쉼표 때문에 레이어가 쪼개지지 않습니다. 명시적인 sRGB RGB/HEX/HSL/transparent와 px/0을 지원하고 P3, unresolved var/currentColor 등은 추측하지 않습니다.

첫 CSS 그림자가 위에 그려지는 순서를 그대로 보존합니다. 비교는 순서 보존 편집 정렬을 사용합니다. 일치 0, 추가/누락 1, 같은 타입의 수치 차이 1.5, 외부/내부 타입 차이 3의 비용으로 대응합니다. 한 겹 삽입으로 뒤의 모든 레이어가 밀리지 않고, 재정렬을 sorting으로 숨기지 않습니다. 추가·누락 행은 재배치 가능성도 설명합니다. 의도된 디자인 레이어의 의미를 자동으로 추정하는 것은 아닙니다.

각 대응 레이어의 X/Y/Blur/Spread/RGBA가 허용오차 안에 있으면 레이어 하나가 일치합니다. 추가/누락은 각각 하나의 불일치, 양쪽 없음은 하나의 일치입니다. 미수집·미지원·사용자 제외는 점수 분모에서 빠집니다. 이 레이어 단위를 기존 속성 일치율에 합산하며 그림자 섹션에도 별도 규격 일치율을 보여줍니다.

## UI와 검증

지원 가능한 그림자는 기본 속성표에, 제외 사유와 Figma 원본 effects/Inspect CSS는 추가 정보에 표시합니다. 색상 HEX/RGB/HSL 변경은 표시만 바꾸며 원본·점수를 유지합니다. 비교 설정의 '그림자' 체크로 제외할 수 있습니다.

`npm run verify`, `npm run test:picker`, `npm run test:browser`를 사용합니다. 기존 설치 Edge를 `FIGCHECK_BROWSER_PATH`로 지정하며 새 권한·라이브러리·브라우저를 추가하지 않습니다. 실제 확장의 DOM computedStyle/DevTools 비교와 빌드된 Figma host/UI 모형을 검사합니다. 실제 Figma 애플리케이션의 getCSSAsync 결과와 물리 OS 단축키는 이 자동화로 검증한 것이 아닙니다.

그림자 UI 캡처: `artifacts/devtools-shadows.png`, `artifacts/figma-shadows.png`. 테스트는 합성 fixture만 사용합니다. GitHub 푸시와 Library 업로드는 이 버전에 포함하지 않습니다.
