# FigCheck 0.2.3 속성 표와 이동 진단

## Figma

선택 노드와 추출 상태 아래에 JSON 복사·파일 저장을 배치하고, 크기/여백·간격/글자/색/테두리·모서리/투명도 그룹에 속성·값·상태를 표시합니다. Padding과 border 4면은 개별 행으로 남습니다. 확인 가능한 값이 있는 그룹은 자동으로 열리고, 전체가 확인 불가인 그룹은 접힌 요약에서 개수를 보여줍니다. 색 견본, CSS px와 sRGB/alpha, 지원·미지원·확인 불가 상태를 구분합니다. 실제 미지원 이유는 해당 행에 있습니다. 긴 이름은 두 줄로 제한하며 원래 이름은 JSON에 남습니다.

JSON 원문은 보조 JSON 보기 버튼에서 열고 키보드로도 접근합니다. 복사·파일 저장은 표 화면에서 바로 됩니다. 복사가 차단되면 원문을 자동으로 열고 선택하여 다시 복사/Ctrl+C로 복구합니다. 선택 변경·새 추출은 이전 표·JSON·복사 상태를 즉시 무효화합니다. 예전 응답은 request ID와 sequence로 무시합니다. 새로 추출은 속성만 바꾸거나 오류를 복구할 때 사용합니다.

## DevTools

양쪽 앱의 한국어 속성명·그룹 순서·단위 포맷은 같은 공통 모듈을 사용합니다. 차이만은 실제 mismatch 행, 전체 속성은 사용자가 포함한 모든 행과 지원 상태를 보여줍니다. 사용자 제외는 어느 표에도 들어가지 않고 별도로 집계합니다. 미지원 이유와 단위 근거는 상세에서 확인합니다. 표에 디자인/웹/웹−디자인 차이를 같은 열로 배치하고 색 견본과 변경 값을 표시합니다. 전체 표는 그룹별로 묶지만 4면 개별 차이는 유지합니다. 현재 비교한 디자인과 DOM의 짧은 식별자를 결과에도 표시합니다.

수치 보정·지원 조건·score 규칙은 바꾸지 않았습니다. 작은 비영 값은 0으로 표시하지 않으며 원본은 JSON/원본 정밀도 상세에서 확인할 수 있습니다. 기존 ? 도움말과 최소 권한을 유지합니다. UX 근거는 [이전 공식 레퍼런스 적용 문서](0.2.2-도움말-UX.md)를 따릅니다. 새 라이브러리와 장식은 추가하지 않았습니다.

## Navigation timeout 진단

0.2.2의 한 시험은 페이지 이동 이전에 실패했습니다. 선택 클릭이 끝나 overlay가 없어지고 DOM 라벨이 갱신되어도, 지속 controller가 다음 250ms heartbeat에서 완료를 확인하기 전에는 active 상태일 수 있습니다. 기존 시험은 이 상태를 새 실행 준비로 간주하고 별도 page owner 테스트를 끼운 뒤 버튼을 눌렀습니다. 버튼은 당시 active 상태에 맞춰 취소를 실행했고, 시험은 없는 새 overlay를 기다려 timeout이 났습니다.

자연스러운 확인 지연에서 동일 상황을 실제 격리 Chrome으로 재현했습니다. 이어 진단 전용 복사본에서 heartbeat 확인을 일시 보류해 조건을 결정적으로 재현하고, 버튼의 응답 active:false와 page/controller 상태를 기록했습니다. 이 보류 제어는 제품 빌드에 없습니다. navigation/picker 제품 코드는 변경하지 않았습니다. 브라우저 회귀는 DOM 라벨뿐 아니라 controller의 inactive 확인까지 기다리도록 수정했습니다. 임의 sleep으로 숨기지 않았습니다.

상태 일치 대기로 12회 새 문서 이동·재선택·Esc·버튼 취소, 6회 겹친 빠른 문서 이동과 재선택, 6회 빠른 Elements 재선택이 통과했습니다. 엔진 테스트에도 실제 controller 소스를 이용한 준비 상태 회귀를 추가했습니다. 결과는 artifacts/navigation-diagnostic-results.json과 navigation-diagnostic-traces.json입니다. 이는 시험한 경로에서 navigation 제품 실패를 확인하지 못했다는 결론이며 모든 웹페이지/브라우저 스케줄을 증명하는 것은 아닙니다.

실제 Figma 호스트와 OS 키→Chrome command 이벤트는 미검증입니다. Figma 화면은 VM host와 실제 Chromium UI의 mock입니다. Chrome 표는 격리된 실제 MV3 DevTools입니다.
