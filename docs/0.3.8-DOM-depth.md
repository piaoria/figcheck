# 0.3.8 · DOM 깊이 탐색

요소 선택 모드에서만 동작합니다. ↑ / Alt+휠 위는 부모, ↓ / Alt+휠 아래는 이전 자식입니다. 클릭 또는 Enter는 윤곽선으로 표시된 현재 요소를 확정합니다. Esc는 취소하며 기존 비교를 보존합니다. Ctrl+Shift+X와 Elements의 $0 선택은 그대로입니다.

## 경로와 입력

- `dom_touch`의 포인터 원본 요소와 탐색 대상을 구분하는 방식을 참고했습니다. 동일한 hit-test 요소 위에서 움직이면 부모 선택을 유지합니다. 다른 요소로 포인터를 옮기면 새 경로를 시작합니다. 3px 미만의 흔들림도 유지합니다.
- 위로 이동할 때 바로 아래 자식을 기억합니다. 아래로 갈 때 연결된 그 자식을 우선 사용하고, 없으면 현재 포인터 아래의 직계 경로만 사용합니다. 무관한 첫 번째 자식을 고르지 않습니다.
- Alt+휠은 픽셀·줄·페이지 단위를 환산해 48px부터 한 단계 이동합니다. 140ms 이내 연속 입력은 버리고, 220ms 쉬거나 방향이 바뀌면 잔량을 초기화합니다. 방향키 자동 반복은 무시합니다.
- Ctrl+휠 확대와 Shift+휠 가로 스크롤을 침범하지 않도록 Alt만 사용합니다. 일반 휠은 취소하지 않습니다. 기존 전체 페이지 선택 overlay 때문에 선택 중 일반 휠의 스크롤 대상은 페이지입니다. 내부 스크롤 영역을 조작하려면 Esc로 선택을 끝냅니다.
- input, textarea, select, contenteditable, textbox에 포커스가 있거나 IME 조합 중이면 방향키·Enter를 소비하지 않습니다. 필드 밖으로 포커스를 옮기거나 Alt+휠을 사용합니다. Esc는 선택 모드를 취소합니다.
- 상단에는 짧은 요소 경로, 방향, 경계 안내만 표시합니다. 문서 내용은 textContent로 표시하며 실행하지 않습니다. 무채색 윤곽선과 UI를 사용하고 페이지에 글꼴·권한·네트워크 의존성을 추가하지 않습니다. 페이지에 Pretendard가 없으면 시스템 글꼴을 사용합니다.

## 경계와 정리

HTML 최상단에서 멈추며 아래 경로가 없으면 그대로 유지합니다. DOM이 제거·이동되면 연결과 부모 관계를 다시 확인하고 잘못된 대상을 확정하지 않습니다. overlay는 hit-test와 자식 경로에서 제외합니다. scroll/resize 시 윤곽선을 다시 그립니다.

지원 범위는 현재 top-level 문서의 HTML입니다. iframe 내부, 열린 Shadow DOM 내부, SVG는 직접 picker 대상이 아닙니다. 닫힌 Shadow DOM은 내부를 볼 수 없어 외부 host만 선택할 수 있습니다. Elements 선택은 기존 수집기의 지원 범위를 따릅니다. 자동 recursive 비교는 없습니다.

Esc·확정·취소 버튼·탭 숨김·페이지 종료·DevTools 연결 만료 시 이벤트, 타이머, overlay를 정리합니다. 재시작은 새로운 탐색 경로로 시작합니다.

## 검증

`npm run verify`로 타입·린트·빌드·핵심 테스트를 실행합니다. `npm run test:picker`는 실제 MV3 확장과 DevTools receiver, command worker를 로드해 깊이 탐색을 검사하며 `artifacts/picker-depth-results.json`과 화면 PNG 두 장을 기록합니다. `npm run test:browser`는 기존 Elements/단축키/확장 UI 및 Figma mock 회귀검사입니다.

설치된 브라우저를 쓰려면 `FIGCHECK_BROWSER_PATH`에 실행 파일을 지정합니다. 2026-10-06 회사 PC에서는 Chrome 154의 자동 unpacked 로드가 불가능했고, 기존 Edge 154와 캐시 Chromium 148은 가능했습니다. 개인 브라우저 프로필에 설치하지 않고 임시 프로필만 사용했습니다. 실제 Figma 호스트와 OS가 가로채는 전역 단축키는 별도 수동 확인 대상입니다.
